# SF12 向 SF11 主项目完整流程对齐 V3 方案

## 1. 方案目的

本方案不是继续在当前 23 符号硬判决适配器上零散增加功能，而是在不修改
SF11 规范主项目的前提下，建立一个独立 V3 工程，将 SF11 Stage55 的完整
实验流程移植到 SF12。

计划中的 V3 目录为：

```text
D:\codex\Lora(eg)\comparison_experiments\stage55_sf12_sf11_flow_v3
```

已有版本保持冻结：

- V1：原始 SF12 硬判决适配实验；
- V2：修正创新门限后的论文条件配对实验；
- V3：SF12 参数下的 SF11 完整 Stage55 流程实验。

V3 不读取或续跑 V1/V2 检查点，也不修改规范 SF11 工程。

## 2. 两类实验身份必须分开

### 2.1 V2：论文条件锚点

V2 保留：

- SF12、BW=125 kHz；
- 120 bit、CR1、23 个数据符号；
- 最后同步 downchirp 的 Point 初始 CFO；
- `n_int=3`；
- Rician K=10 dB；
- Paper Case1/Case2 固定位置；
- Paper Midamble-Point 论文公式口径。

V2 用于回答“公开论文条件下的独立复现”和论文图像端点差异问题。

### 2.2 V3：SF11 主流程的 SF12 移植

V3 将采用：

- CR3 Hamming(7,4)；
- 完整编码、Gray 映射与对角交织；
- 8 个已知 upchirp 公共 bootstrap；
- 接收机可见的前导 CFO/相位速率；
- Stage55 最多 5 次软置信迭代；
- 因果虚拟导频接纳；
- rolling-8 CFO/速率拟合；
- 相位对 CFO、连续相位补偿和不确定度融合；
- 因果跨帧 rolling-8 状态；
- 连续过境和完整帧调度；
- 包/过境级配对统计；
- SER、硬 BER、ML 软 BER、PER、CFO、goodput 和复杂度报告。

由于 V3 改变了编码、Payload、bootstrap 和帧流，它的 Paper 分支必须命名为：

```text
Paper-Midamble-Point-SF12-CR3-adapted
```

不能把 V3 的 Paper 曲线称为论文 Figure 10/11 原条件曲线。

## 3. V3 与 SF11 主项目保持相同的内容

V3 应与规范 SF11 项目保持以下流程一致：

1. 使用同一 Hamming(7,4) 码表；
2. 使用同一 Gray 编解码方向；
3. 使用同一 LoRa 对角交织/解交织顺序；
4. 使用同一 8 前导公共 bootstrap 结构；
5. 使用同一最多 5 次 SenLoRa 置信迭代；
6. 软信息只决定虚拟导频接纳，虚拟导频标签仍来自硬 LoRa 判决；
7. 完整 7 符号 Hamming 块到达后，置信结果才可因果地影响后续符号；
8. 使用固定 8 槽 rolling 历史；
9. 使用历史衰减、peak 权重和 Huber 鲁棒拟合；
10. 使用单符号 CFO 融合、受保护的相位对 CFO 和速率可观测性门；
11. 载荷真值和轨道真值只进入外层审计，不进入接收机接口；
12. 连续相位跨符号、跨帧传递；
13. 帧间使用模 `2*pi` 相位状态，避免长过境大数精度损失；
14. 跨帧速率状态只来自历史前导 CFO 观测；
15. 修改算法后使用全新结果目录和全新随机种子；
16. 正式统计以完整过境为重采样单位，使用配对 bootstrap；
17. 保存逐帧记录、随机账本、检查点和算法签名；
18. 单独报告复杂度、deadline、PER 和 goodput，不能只报告有利 SER/BER。

## 4. V3 与 SF11 仍然存在的差异

下表是必须在报告中长期保留的差异，不能因为流程已经对齐而省略。

| 项目 | SF11 规范主项目 | SF12 V3 | 影响 |
|---|---:|---:|---|
| SF | 11 | 12 | FFT 和软符号维度变化 |
| 带宽/采样率 | 250 kHz | 125 kHz | 符号时间和噪声带宽变化 |
| 每符号采样数 | 2048 | 4096 | 单次 FFT 复杂度增加 |
| 符号时间 | 8.192 ms | 32.768 ms | 相同 Doppler rate 下单符号漂移约增加 4 倍 |
| FFT bin | 122.0703 Hz | 30.5176 Hz | CFO、速率和门限必须重新量纲化 |
| LDRO | 普通 SF11 处理 | 开启 | SF12 只允许 spacing-4 数据标签 |
| 有效数据位宽 | 11 bit/符号块行 | 10 bit（SF−2） | CR3 编码器不能直接使用12行旧矩阵 |
| CR | 3 | 3 | 相同 |
| Hamming块数 | 16 | 16（建议） | 保持112个载荷符号 |
| 信息位数 | 16×11×4=704 bit | 16×10×4=640 bit | LDRO导致每块少4信息位 |
| 载荷符号 | 112 | 112 | 保持SF11迭代/覆盖流程 |
| 无Midamble帧时长 | 0.98304 s | 3.93216 s | 过境内帧数明显减少 |
| Paper `n_int` | SF11移植值48 | SF12论文值3 | V3 Paper显式导频远密于SF11 |
| 112符号Midamble | 2个 | `ceil(112/3)=38`个 | Paper ToA/能耗显著增加 |
| 信道 | 规范主结果主要为AWGN+Doppler | SF12保留Rician K=10 dB为主口径 | 衰落和跨帧状态耦合不同 |
| SNR正式点 | 主要−21、−20 dB | 用户目标−30:−21 dB | V3计算量更大 |
| 论文Case | SF11高频偏/高速率可见区域 | V3连续过境区域 | 不再等于论文固定Case1/Case2单包定义 |
| Paper初始化 | 共同8-upchirp bootstrap移植 | 同SF11流程 | 不再是论文最后downchirp Point原条件 |

### 4.1 关键 LDRO 差异

不能把 SF11 编码器简单设置 `config.sf=12` 后直接运行。原函数会生成 12 行
Hamming 数据并允许全部 4096 个符号标签，这与 SF12 LDRO 的 1024 个合法标签
不一致。

V3 必须显式定义：

```text
physicalSf = 12
effectiveDataSf = 10
dataAlphabetSize = 1024
dataBinSpacing = 4
```

编码、Hamming、交织和 LLR 使用 `effectiveDataSf=10`；波形生成和 FFT 使用
`physicalSf=12`；最终波形 bin 为逻辑符号标签乘以4。

## 5. V3 方法设置

正式主比较保留与 SF11 三方法流程相同的三个分支：

1. `Huang-PREC-static-CP-SF12`：公共 bootstrap 后固定 CFO，作为控制；
2. `Stage55-VP-quality-CR3-SF12`：完整 Stage55；
3. `Paper-Midamble-Point-SF12-CR3-adapted`：已知 Midamble 分段常数更新。

三种方法必须共享：

- 同一编码 Payload；
- 同一连续 Doppler 相位；
- 同一 Rician 系数和 AWGN 数组；
- 同一公共8前导bootstrap CFO与起始相位；
- 同一数据符号物理时刻；
- 同一随机账本；
- 同一最终硬/软Hamming译码口径。

Paper 使用显式 Midamble；Stage55 和 Huang 在算法接口中忽略 Midamble，但在
公共物理帧中仍推进对应时间。

## 6. 跨帧状态与轨道先验的选择

V3 选择：

```text
因果跨帧 rolling-8 前导 CFO 状态
```

V3 不选择：

```text
轨道真值速率先验
```

理由：最新 SF11 Stage55 的规范路径明确输出 `usesOrbitPrior=false`。跨帧状态
完全来自接收机可见的历史前导 CFO，符合因果性；轨道真值先验会改变公平性，
也会使性能收益无法归因于虚拟导频。

孤立帧没有足够跨帧历史时，回退到8前导相位拟合速率。跨帧历史达到8帧后，
使用固定 rolling-8 加权速率估计。

## 7. CR3、软Hamming与LDRO适配

### 7.1 Payload定义

建议保持 SF11 的16个完整Hamming块：

```text
16 blocks × 7 coded symbols = 112 payload symbols
16 blocks × 10 rows × 4 data bits = 640 information bits
```

这样可以保持与SF11一致的：

- 迭代次数；
- 块级置信时序；
- 虚拟导频候选长度；
- rolling覆盖统计；
- SER/BER/PER流程。

### 7.2 软符号概率

SF12接收端仍执行4096点FFT，但软译码只能形成1024个合法LDRO符号的概率。
每个合法符号对应一个spacing-4中心。细FFT峰用于CFO容差，符号概率必须按照
合法符号判决区域聚合，之后再计算10位Gray LLR。

必须用以下测试锁定：

- 1024个合法符号逐个无噪声往返零错误；
- 所有输出bin都是4的倍数；
- 硬判决与软最大后验标签一致；
- CR3编码、交织、解交织、硬Hamming和ML软Hamming逐块往返一致；
- 不允许第11、12物理bit误入LDRO数据码字。

## 8. 连续帧和物理信道

V3复用SF11的连续过境调度思想，但所有帧时刻必须按SF12实际帧长重新计算，
不能继续使用SF11的0.98304 s帧周期。

物理链要求：

1. Doppler频率逐采样计算；
2. 相位由频率逐采样积分；
3. 相位跨数据、Midamble和帧边界连续；
4. Rician主口径为K=10 dB；
5. Rician时间相关模型仍采用明确标注的packet-flat实现；
6. AWGN功率按带宽B内单位平均发射功率定义；
7. 三方法接收完全相同的复数样本；
8. 盲区/不可见帧只推进时间、相位和信道状态，不进入通信指标。

同时保留AWGN-only机制基线，用于区分软译码错误和Rician衰落错误；它不是
第四种主算法曲线。

## 9. Paper分支边界

V3 Paper分支保留论文机制：

- 已知纯upchirp Midamble；
- `n_int=3`；
- 每个Midamble估计当前补偿后的残余CFO；
- 按式（17）累加残余CFO；
- Midamble之间采用分段常数补偿；
- 不使用Payload判决作为导频。

但它与论文原图存在以下明确差异：

- CR1改为CR3；
- 23符号改为112符号；
- 最后downchirp Point改为共同8-upchirp bootstrap；
- 单包Case改为连续帧流；
- 三方法使用共同配对样本和共同软Hamming输出。

因此论文−21 dB图像端点只能由V2评价，不能作为V3 Paper分支的数值验收门。

## 10. Stage55移植范围

从SF11规范项目移植并参数化以下核心模块：

- Payload生成、Gray、交织和硬Hamming；
- FFT能量概率、bit LLR和ML软Hamming；
- 公共8前导联合CFO/相位/速率bootstrap；
- rolling-8 Pilot Tracker；
- 最多5次SenLoRa置信迭代；
- 单符号和相位对CFO融合；
- 虚拟导频速率可观测性门；
- 因果跨帧速率状态；
- 连续过境帧生成、检查点、报告和复杂度计数。

不得直接依赖SF11工作目录运行。V3应复制必要核心文件，并在
`config/source_manifest.json` 中保存原文件路径和SHA-256，确保V3自包含且
不会被SF11后续修改静默影响。

## 11. 参数标定原则

SF11阈值不能原数值照搬到SF12。以下参数必须按SF12重新标定：

- bootstrap搜索步长；
- 单符号CFO标准差；
- 创新门限；
- Huber门限；
- 相位对创新和一致性门限；
- VP速率标准差门限；
- 软Hamming margin ratio；
- SNR置信窗口；
- 历史速率偏离限制。

标定流程：

1. 先做无噪声量纲验证；
2. 使用独立mechanism-calibration种子；
3. 只测CFO误差、置信覆盖、误接纳和速率可观测性；
4. 不读取V1/V2正式SER；
5. 不读取论文图像marker作为参数输入；
6. 参数冻结后写入manifest和算法签名；
7. 使用另一组validation种子运行Case/区域验证；
8. validation失败时必须说明机理并建立新版本，不能在正式结果上循环调参。

### 阶段8：报告和复杂度

- Case/区域SER-SNR；

## 13. 随机账本

V3使用与SF11、V1、V2均不重叠的新种子域，例如：

```text
机制标定 payload/noise/channel: 202801xx / 202802xx / 202803xx
独立验证 payload/noise/channel: 202811xx / 202812xx / 202813xx
正式过境 payload/noise/channel: 202821xx / 202822xx / 202823xx
bootstrap重采样:               202824xx
```

最终实现必须使用跨度足够大的整数域，并自动枚举验证不存在交集，不能只比较
相同包索引的三个种子。

## 14. 测试与审计门

### 14.1 编码和LDRO

- 1024合法符号零错误往返；
- CR3全部16个码字逐项验证；
- 16个随机块硬/软解码无噪声一致；
- 物理bin全部为4的倍数。

### 14.2 物理链

- 无噪声无Doppler零SER/BER/PER；
- Case/过境轨迹范围正确；
- 逐采样相位积分和跨帧桥接误差通过；
- Rician单位平均功率通过。

### 14.3 公平性

- 三方法公共样本指纹完全相同；
- bootstrap CFO、相位逐元素相同；
- Stage55/Huang显式Midamble接纳为0；
- Paper虚拟导频接纳为0；
- 接收机接口无Payload/轨道真值；
- 所有方法使用同一软Hamming最终指标。

### 14.4 Stage55机制

- 置信结果只在完整7符号块之后生效；
- rolling历史始终最多8项；
- 跨帧状态时间严格递增；
- 相位对必须同时通过创新和单符号一致性门；
- VP速率只有达到可观测性标准后才能替代bootstrap速率；
- validation误接纳率和覆盖率满足预注册门。

### 14.5 统计与恢复

- SER/BER/PER严格来自原始计数；
- 配对bootstrap以完整过境为单位；
- 单次过境只能标记为wiring；
- checkpoint恢复与连续执行逐项一致；
- 代码/配置/种子签名不一致时拒绝恢复；
- MATLAB Code Analyzer为0问题；
- V3测试不得读取V1/V2正式结果作为性能门。

## 15. 性能目标的正确使用

用户期望：

1. Stage55在`-30:-21 dB`位于Paper下方；
2. Paper结果与论文趋势一致。

V3将这两项记录为盲测观察目标，但不得用于参数反向搜索或成为单元测试中的
强制曲线断言。

原因：

- CR3、112符号和共同8前导使V3 Paper不再是论文原条件；
- 极低SNR下已知Midamble在信息上可能优于判决驱动VP；
- 强制每个点排序会把随机波动转化为调参目标。

正式参数冻结后只运行一次正式种子。如果某点没有满足排序，应原样报告；只有发现
可独立证明的代码或机理错误时，才建立新的版本重新标定和从零运行。

论文图像−21 dB端点继续由V2报告，V3不得用改变Paper信道或故意降低Paper性能
的方式制造Stage55优势。

## 17. 实施完成标准

V3完成不以指定曲线形状为唯一标准，而以以下条件共同成立为准：

1. SF11完整Stage55流程已在SF12/LDRO维度正确运行；
2. CR3硬/软Hamming链经过独立验证；
3. 连续帧、跨帧状态和相位连续性通过；
4. 三方法公共样本和bootstrap公平性通过；
5. 参数未由正式曲线或论文marker反向选择；
